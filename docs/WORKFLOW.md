# 개발 협업 방식

## 이슈로 협업 (자동)

모든 작업과 검토 의견은 GitHub 이슈와 PR에 남긴다. 채팅으로 설명을 반복하지 않고, 각 AI는 이슈에 적힌 범위의 코드만 읽는다.

1. **작업 = 이슈 1개.** 본문은 템플릿 5줄(목표·담당·브랜치/기준·수정 범위·완료 조건). 담당은 라벨 `claude` 또는 `codex`. 형의 결정이 필요하면 `형-결정` 라벨.
2. **시작할 때** 담당자가 이슈에 "시작: 브랜치 이름" 코멘트를 남긴다. 같은 파일을 다른 이슈가 수정 중이면 기다리거나 그 이슈에 코멘트로 조율한다.
3. **끝나면 PR.** PR 본문 첫 줄 `Closes #번호`. PR에 `needs-review` 라벨을 달고, 상대에게 넘긴다: Codex 검토는 PR 코멘트 `@codex review`, Claude 검토는 라벨 `claude`.
4. **검토 결과**는 PR 리뷰 코멘트로. 이번 PR에서 고칠 것은 담당자가 고치고, 나중 일은 새 이슈로 만든다(코멘트에 묻히지 않게).
5. **인수인계**는 이슈 코멘트 한 개: 한 일, 남은 일, 다음 명령. `docs/HANDOVER.md`에는 코드 구조가 바뀔 때만 쓴다.
6. **자동 점검**: Claude는 정해진 시간마다 열린 `claude` 이슈와 `needs-review` PR을 확인해 처리한다. 할 일이 없으면 바로 끝난다. Codex는 `@codex` 코멘트가 달리면 그 이슈·PR을 처리한다(Codex 설정에서 GitHub 연동과 자동 리뷰를 켜야 함).

형은 "이슈 만들어줘" 또는 이슈 하나만 쓰면 된다. 우선순위를 바꾸려면 이슈에 코멘트를 남긴다.

## 코드와 배포

- 수치와 업그레이드는 `prototype/balance.js`; 게임 규칙은 `prototype/game.js`; 화면은 `prototype/index.html`과 `prototype/style.css`에서 수정한다.
- 공개용 `gh-pages`는 `prototype/` 내용을 루트에 복사한 배포 브랜치다. `main`에 머지한 뒤 `main:prototype/`에서 복사해 갱신하고, Pages 설정이 어느 브랜치를 보는지 확인한다. 배포 때 `version.json`에 배포 커밋 sha를 써야 열려 있는 게임에 업데이트 알림이 뜬다.
- `main` = 최신 웹 게임. 작업은 이슈별 브랜치에서 하고 PR로 `main`에 합친다.
- 수정 전후 `git status`, `git log -1`, `git diff --check`, `node --check prototype/game.js`, `node --check prototype/balance.js`를 확인한다.
- GitHub Actions가 JavaScript 문법을 검사한다. 통과해도 모바일 조작과 실제 재미가 검증된 것은 아니다.
- 휴대폰 크기 브라우저에서 시작, 채집·판매, 눈보라, 저장·이어하기를 확인한다. 수치 변경은 `docs/GDD.md`와 `docs/PLAYTEST.md`에 기록한다.
